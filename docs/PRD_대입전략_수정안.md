# PRD: 이즈유 대입전략 웹서비스 개편 (수정안 반영)

- **문서버전** v1.0 · **작성일** 2026-07-05
- **소스** 수정안.docx(2026-06-29) + 대표님 Notion "프롬프트 포트폴리오(이즈유)"(2026-07-05) — 두 소스 통합·중복 제거
- **대상 앱** College-Admissions-Strategy-Web-Service (현행 1~5단계 구조)

> 표기 규칙: 각 요구사항 = `현황(as-is) → 변경(to-be) → 수용기준(AC)`, 우선순위 **P0**(시연 필수)/**P1**/**P2**. 확정 문구는 " " 안 그대로 사용.

---

## 1. 개요·배경
5등급제 내신을 과거 9등급 입결에 투영해 **현재 위치 진단 → 수시 지원 가능 대학(교과·종합) → 종합전형 선택과목 추천 → 최종 보고서**까지 한 흐름으로 제공하는 웹서비스(이즈유 대입성공매니지먼트 · 클럽하와이 학원 제휴).

이번 개편은 대표님/현장 피드백(수정안·Notion)을 반영해 **흐름·문구·필터·AI·마이페이지**를 정비하고 설명회 시연 완성도를 높이는 것이 목적이다.

**핵심 문제(현행)**
1. 탭 자유이동으로 단계를 건너뜀
2. 성적 미입력 상태에서도 상위 단계가 활성화됨
3. 페이지 제목/설명 문구가 불명확·어색함
4. 인문계열 종합 선택과목 데이터 공백
5. 마이페이지·최종 보고서 부재

## 2. 목표 / 비목표
- **목표**: 선형 스텝 흐름, 명확한 확정 문구, 지역·전형·구분 필터, AI 기반 5단계·보고서, 마이페이지·계정관리.
- **비목표(현 단계 보류)**: 일일 사용횟수 제한 + 자정 리셋(구현 복잡·시연 리스크), 5단계 이후 AI 자동화·최종 보고서 자동생성은 후속.

## 3. 대상 사용자
학생(고1~3)·학부모 / 컨설턴트(원장·강사) / 서비스 관리자.

## 4. 현재 상태(as-is) 요약
1 성적입력 · 2 환산 · 3 교과전형 준비전략 · 4 지원 가능 대학·학과 · 5 종합 선택과목 추천의 **탭 네비게이션**. Supabase 연동(단계별 DB·usage_events), 관리자(단계별 DB 관리 + 계정별 **사용 횟수** 조회 — 이미 구현), 5단계는 정적 선택과목 DB(47개 대학).

## 6. 비기능 요구
글자크기 통일(2단계 강조), 웹/모바일 반응형(기반영), 접근성, 시연 안정성 우선.

## 7. AI 연동 (Claude API)
5단계 선택과목 근거 설명 + 최종 보고서 자동생성에 Claude API 사용(현재 미구현). **API 키를 개발자 계정 → 의뢰인(박 이사장) 계정으로 이전** 필요. 설명회 당일 집중 사용 시 **비용 급증** 우려 → 사용량/키 관리 방안 필요.

## 8. 데이터
기존 DB(대학학과입결·교과전략·5↔9 환산·종합 선택과목) 활용. **인문계열 종합 선택과목 데이터 공백** → AI 또는 타 대학(숙대·동대) 자료로 대체. 성적 입력은 국수영사과로 범위 축소(REQ-06).

## 9. 릴리스 계획
- **Phase 1 (시연 대비·P0, ~4단계)**: 흐름 개편(선형·뒤로가기·미입력 비활성)·확정 문구·범위 축소·지역/전형/구분 필터·상세 팝업 버튼화·5단계 진입 안내.
- **Phase 2 (P1)**: 5단계 AI 설명·최종 보고서·마이페이지·계정 활성/비활성·드래그앤드롭·정렬.
- **보류**: 일일 사용 제한(REQ-70).

## 10. 오픈 이슈 / 리스크
- **API 비용·키 이전**(박 이사장 계정), **도메인**(박 이사장 보유) 적용, **GitHub 레포 이관** 방법(강사 문의).
- **드래그앤드롭** 구현 난이도(P1, 확인 후 확정).
- 4단계까지 개발 가능 확인, **5단계 이후·자동화 미완성**.
